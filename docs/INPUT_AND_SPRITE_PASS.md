# 0.8.2 鍵盤與角色動態修正批次

2026-09-18。這是既有修正的整合發布，不是重做遊戲。Exact source、CI與交付位置以 STATUS.md 及 DELIVERY_INDEX.md 為準。

## 問題、修正與驗證

既有程式把方向鍵／Enter固定交給P2，單人狀態又拒絕P2指令；勝利畫面缺少鍵盤繼續路徑，對話依賴瀏覽器按鈕預設行為，匯入檔案後焦點可能留在file input。這些是已讀程式確認的缺口，不冒稱已重現使用者裝置的每一種失效原因。

本批 keyboard-policy.ts 明定單人方向鍵／WASD操作P1、雙人方向鍵仍只操作P2。main.ts先處理標題、對話、選項、暫停、背包與戰鬥結果，再送世界指令；Enter／E／空白確認只執行一次。保留Tab導覽、真正文字輸入與瀏覽器快捷鍵，canvas在開始／關閉選單／結果／匯入／取消後取得焦點。H與畫面提示顯示目前控制方式。input.ts另外處理C切換雙人時的持續長按及auto-repeat，不把P2既有方向鍵轉交P1；釋放後的新按鍵正常生效。

新的keyboard_browser.py用真實按鍵走標題、房間、樓梯、母親、大地圖、廣場、Gato原地ATB、勝利繼續、Tab/Enter匯出匯入、暫停和P2控制權。只讀snapshot/view，沒有直接設旗標、瞬移、製造存檔或加速模擬。保留之前九段瀏覽器流程及good/bad新遊戲到法庭路線，沒有刪除原斷言。

## 像素呈現不是單純加粗黑邊

既有48×64角色已有深色外輪廓。粗糙感還包含頭身與側姿、內部明暗、像素密度、缺少待機／戰鬥準備變化、腳底定位及材質偏色。此批沿用原生座標繪製，新增四角色呼吸、眨眼、衣物變化、武器準備姿勢；八名已登錄配角有四個環境動作姿勢。這不是所有NPC都已自由走動、所有角色都完成原版幀序。

PosePlayer處理idle/ready/walk與既有動作，暫停不推進呈現時間。NpcMotion只在有效姿勢改變時重畫，不能更改任務NPC座標或劇情。像素材質使用單次非受光的emissive illumination與零常數emission/specular/ambient，避免同圖重複貢獻與舊灰色發光值改變色彩；重用材質也重新檢查。lit場景、透明混合特效與不同貼圖材質不套用。NullEngine驗證的是實際旗標，不等於已看過新GPU畫面。角色依腳底pivot與相機up向量定位，增加小型接地陰影；碰撞與ATB不改。

新主角圖集416×1088、每人128筆幀資料；配角208×68、每人4幀。整包57組PNG/JSON、969筆幀資料包含既有素材與定格重複，不是969张獨特原作動畫。idle1500/1500/150/850ms、ready300ms為本案自訂，不是ROM抽取；PNG與runtime共用繪製函式，外部編修PNG的通用回匯仍未完成。
