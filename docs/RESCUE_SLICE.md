# Cathedral rescue 0.6 — scope and acceptance contract

The prior mainline ended with Lucca joining and the western forest exit. This slice continues from that exact v4 checkpoint, without replay requirements or resetting the fair/kingdom. Main purpose: a coherent playable rescue and first real three-actor party, not another disconnected technical demo.

## Implemented route

Nave crest investigation → 3 Naga ambush → explicit Frog recruitment → western organ opens the concealed door → passage supply chest and 3 guards → Yakra false-chancellor fight → optional real chancellor in box and explicit queen rescue → escort to castle → Marle reappears upstairs → walk back through forest/town/canyon → time gate returns all three to 1000 AD.

The three maps deliberately compress the original dungeon. Full room topology, traps/switch network, exact encounters, hidden items, dialogue script and original combat math are not implemented. Trial is the next unavailable chapter; the game says so at the return boundary. The queen escort is an explicit narrative scene transition, not a fabricated walking/cinematic simulation. Frog recruitment/rescue dialogue is newly written, not verbatim source extraction.

## Actors and combat

P1 Crono and P2 Lucca retain existing input ownership. Frog is a third real autonomous actor with his own HP 140, MP 16 and ATB .38/second; normal attack 26, or wounded-ally recovery up to 36 at 3 MP when below 55% health. These are provisional balance values. It uses shared collision-aware A* on exploration; it is a valid enemy target and must also be defeated for total-party loss. A dead/absent guest cannot act. No third human control, free party switch or triple tech is implied.

Human ATB .42, old damage/MP and both-player combo accounting remain unchanged. Naga HP60, guards64; Yakra HP720, ATB .22, normal damage18 and every third action12 across living actors, with readiness warning. Prototype patterns, not original move-set/numeric claims. Victories/defeats recover stats when continuing, matching the existing accessible slice rules rather than asserting original difficulty.

Passage chest gives exactly three tonics once. A tonic needs full ATB and a wounded living issuing actor, consumes one stock and ATB, heals up to50 and leaves MP intact. U/P1, backslash/P2 or visible UI; no gamepad shortcut yet. Not a full inventory/equipment implementation.

Frog leaves after queen homecoming; Marle later joins as autonomous third ally. P2 is not silently reassigned away from Lucca. The reunited party can leave the castle, traverse town/forest/canyon and take the northern gate back to present fair. The old disappearance event does not restart there.

## Art

Original 2D cathedral composition was visually checked: organ, red carpet, fluted dark columns, stained glass, patterned stone. Its published screenshot's platform/revision is unverified; it is not labeled as a verified SNES capture. The static SNESMaps Frog sprite was also visually inspected. Sources/limits in reference-index. Existing original-image calibration of Crono/Marle/Lucca is retained.

New room surfaces and geometry are authored code: no sampled original pixels, ROM or soundtrack. Frog uses timed hand-authored directional walk/combat poses and the real render event stream. Yakra/Naga redraws are provisional rather than frame-verified original reproductions. Lazy map creation and common solid footprints reduce collision/visible-object mismatch; no full streaming or hardware performance claim.

## Persistence

v1-v4 keep their existing schema. A rescue-stage game exports v5; exact branch depends on actual stage, not just a version label. v5 whitelists stable rescue and guest fields, rejects invalid map/era/prerequisite combinations, non-finite/out-of-bounds stats and unearned stock, and resets transient ATB/cache/effects. Same indexedDB adventure slot, no new backend or account. No migration writes destroy a previous save on import failure.

## Validation

Unit tests cover story gating, valid/invalid v5, stock, separate third-actor ATB/MP, enemy targetability, healing/death, loss/retry, explicit recruitment/homecoming, return and a continuous normal-input route. Art tests include PNG consistency and all Frog export/runtime walking frame parity.

New rescue browser journey must read the real v4 export generated by the preceding kingdom journey in the same CI. It performs only UI import, keyboard, buttons, real storage/export/reload, and readonly observations. Failure report retains exact stage, party, waits, FPS, view and screenshot; no removed old assertion, direct-state setter or speed-up hook.

Browser success is not final visual approval, proof of original accuracy or complete-game acceptance. No numerical quality uplift without fresh source-matched captures; whole-game gate remains blocked. Current live deployment must continue serving last validated CI artifact until the new full CI passes.
